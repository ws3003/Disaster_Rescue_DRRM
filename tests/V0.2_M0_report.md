## 1. 交付内容

### 1.1 数据流（新增视频链路）

```
video 文件
  → VideoFrameReader.iter_frames(frame_stride)     # src/video.py, 纯 I/O
      yield (frame_idx 源帧号, t_sec=idx/fps, frame BGR)
  → process_one(...)                               # src/main.py, 与图片模式同一函数
      detector → pose → state → risk → ranking → 可视化 (算法零改动)
  → ① VideoFrameWriter: outputs/videos/<stem>_annotated.mp4 (逐帧标注, 含排序榜)
  → ② JSONL 特征流:      outputs/stream/<stem>.jsonl
      header 行 (视频元数据) + 每帧一行感知记录 (无人帧 persons=[] 也写出)
```

### 1.2 JSONL 特征流 schema（PRD 4.2 接口，M2/M3 离线重放用）

```json
{"type":"header","version":"0.2-m0","video_path":"...","fps":12.0,
 "width":720,"height":960,"total_frames":60,"frame_stride":1,"device":"cuda"}
{"type":"frame","frame_idx":0,"t_sec":0.0,"persons":[
  {"pid":1,"class_name":"civilian","bbox":[232.81,60.32,532.01,928.85],"det_conf":0.8961,
   "pose_ok":true,"pose_vis":0.9652,
   "landmarks":[[0.5836,0.1878,1.0], ...33组归一化坐标 (x/W, y/H, visibility)],
   "state":"Standing","state_conf":0.7873,
   "f1":0.382,"f6":0.932,"risk_score":0.3561,"priority":"LOW","rank":1}]}
```

- `pid` 为**帧内编号**（M0 无跟踪器，每帧重置）；M2 在此 schema 上**追加** `track_id`，不改既有字段；
- rescuer 仅 `{pid, class_name, bbox, det_conf, pose_ok:false}`（与图片模式一致，不做姿态/状态/风险）；
- `landmarks` 归一化坐标配合 header 的 width/height 可还原像素；`video.stream_landmarks: false` 可关闭；
- 输出 fps = 源 fps / frame_stride，保证抽帧后回放时长与源视频一致。

## 4. 关键设计决策与实测发现

1. **无损编码做 golden**：mp4v 为有损压缩（实测 roundtrip 像素 maxdiff≈59），曾导致边界检测漂移：001 重复框被 NMS 合并（2 人→1 人）、002 边界姿态 Standing/Sitting 翻转（f1 漂移 0.07）、005 多出 1 个 FP、bbox 偏移 6–8px。框架 golden 的目的是证明**视频管线自身零漂移**，故冒烟视频改用 **HFYU HuffYUV 无损 .avi**（实测 roundtrip maxdiff=0），golden 逐位比对通过。真实视频的有损压缩鲁棒性是感知层话题，留待 M3+ 多样本验证。
2. **letterbox 底部对齐**：测试图混有竖图（1440×1920）与横图（005 为 708×531）。直接 resize 破坏长宽比（横图拉成竖图，人体几何失真）；居中黑边又使 005 坐姿图脚下大片黑边，pose.py 的脚部方向 3× ROI 扩边伸进黑边，MediaPipe 返回无关键点。最终方案：等比缩放 + **底部对齐**（脚部贴近画布底边，黑边只在上方），005 在视频段恢复 Sitting 且 12/12 稳定。
3. **MediaPipe 保持 static_image_mode=True**：ROI 裁剪逐人推理，每帧裁剪图是独立图像，MediaPipe 内部跨帧跟踪不生效；跨帧身份关联是 M2 自有跟踪器（PRD 5.2，纯 numpy/OpenCV）的职责。
4. **特征流即 PRD 4.2 解耦接口**：M2 跟踪器、M3 TSF、动态 DRRM 后续直接消费 JSONL 离线重放，不必反复跑视频。

## 5. 存在问题与限制

1. **无真实灾场视频**：当前以测试图合成视频验证框架；脚本化视频拍摄（PRD 11.2 Week3 的 8–12 段）尚未开始。
2. **pid 帧内重置**：M0 无跨帧身份，同一人在相邻帧 pid 可能不同——M2 跟踪器（IoU 为主 + 关键点几何相似为辅）解决。
3. **无时序能力**：TSF 状态机/防抖/Static Lying、F2–F5 动态因子、rank_delta/重排归因均未实现（M3+）；Fall 仍依赖单帧几何（002 限制不变）。
4. **标注视频体积**：当前标注输出用 mp4v（有损，516KB/60帧@720×960），仅供目视；特征流是无损数值记录，不受影响。
5. **无损冒烟视频体积**：HFYU .avi 约 47 MB（720×960×60 帧），位于 outputs/test_assets/（gitignore 内，不入库）。
6. **未清理项**：outputs/test_assets/ 下残留早期调试文件 smoke_video.mp4 与 _codec_test.*（均为 outputs/ 内 gitignored 产物），未删除（删除操作待用户确认）。
7. `evaluate_states.py` 退出码为 1（3/5 未达满分即非零），与 V0.1.5 行为一致，非本次回归引入。
