## 2. 设计要点

1. **鸭子接口复用**: `CameraFrameReader` 暴露 `fps/width/height/total_frames` 属性 +
   `iter_frames(frame_stride)` 生成器 (yield `frame_idx, t_sec, frame_bgr`) +
   上下文管理器, 与 `VideoFrameReader` 完全同构。`run_camera` 循环体与 `run_video`
   同构, 逐帧调用同一 `process_one()`, **YOLO/MediaPipe/state/risk/ranking 零改动**。
2. **背压取帧**: `capture_array()` 处理一帧抓一帧 (阻塞取最新帧); 推理慢于采集时
   驱动自动丢弃积压旧帧, 不堆队列、不占内存。实测吞吐 = 推理速度, 与采集 fps 上限无关。
3. **延迟导入 + 友好报错**: `picamera2` 在 `CameraFrameReader.__init__` 内导入;
   Windows/无包环境抛含 `sudo apt install python3-picamera2` 指引的 RuntimeError,
   `run_camera` 转为 SystemExit 友好退出 (无 traceback, 退出码 1)。
4. **实时产物**:
   - 实时标注窗口 `cv2.imshow` (bbox/骨架/状态/风险/Top-K 排序榜, q 键退出);
   - JSONL 特征流 `outputs/stream/camera_<时间戳>.jsonl` (header `video_path=picamera2`,
     `total_frames=0` 标记实时流; schema 与 V0.2-M0 视频流完全一致, M2/M3 可直接消费);
   - 可选标注视频录制 `outputs/videos/camera_<时间戳>_annotated.mp4` (默认关, 省 Pi 编码开销)。
5. **优雅退出**: q 键 / Ctrl+C 均释放摄像头与 VideoWriter、销毁窗口, 并打印
   处理帧数 / 含人员帧 / 实测 FPS。
6. **headless 支持**: `camera.show_window: false` 时不调用任何 GUI 函数
   (无桌面环境纯 JSONL 运行), Ctrl+C 退出。
7. **每帧独立推理**: MediaPipe 保持 `static_image_mode=True` (与 V0.2-M0 一致),
   跨帧关联属 M2 跟踪器职责; pid 仍为帧内编号。

## 5. 已知限制 / 边界

1. **仅 Picamera2 (CSI 摄像头)**, 不提供 USB 摄像头 / Windows 摄像头实现;
2. **无跨帧身份**: pid 帧内重置 (同一人相邻帧 pid 可能不同) — M2 跟踪器解决;
3. **无时序能力**: Fall 仍靠单帧几何, F2–F5 仍 alpha=0 — M3 TSF / 动态 DRRM;
4. 实时流 JSONL 的 `fps` 为采集上限配置值, 实际吞吐看结束统计的实测 FPS;
5. 窗口模式需桌面环境; headless 须置 `camera.show_window: false`;
6. Pi 上 MediaPipe/ultralytics 的 ARM64 安装与 CPU 性能为部署期事项, 本阶段代码不涉及。
