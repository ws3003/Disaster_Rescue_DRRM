# V4.4 A 线微信小程序（首期三页）

本目录是 V4.4 A 线的微信小程序实现，依据：

- `docs/灾害现场智能监测与语音交互系统_v4.4_SRS_v0.8R1.md`
- `《V4.4 A 线正式执行任务书（定稿）》`
- `schemas/s4_contract.json`（契约版本 `0.1.0`）

首期只包含三个页面：

| 页面 | 路径 | 使用接口 |
|---|---|---|
| 首页 | `pages/home/index` | S4-01、S4-02（按 category 分别请求两组） |
| 告警列表 | `pages/alerts/index` | S4-02 |
| 告警详情 | `pages/detail/index` | S4-03、S4-04 |

S4-06（环境读数）契约保留，但按任务书首期不新增第四个页面。

## 首页信息来源与契约边界

- **系统运行状态**：S4-01。契约当前把 `device.status` 固定为占位值 `unknown`，
  `modules` 为空对象，且 `implementation_status=placeholder_not_implemented`。
  页面只如实展示占位结构，不补任何未经契约定义的字段。
- **最近告警**：S4-02 分别以 `category=person` 与 `category=sensor_environment`
  请求第 1 页（`page_size=3`），两组各自保持服务端顺序。
  契约明确禁止跨组全局时间排序，因此首页是“分组最近”，不是全局时间合并。
- **高风险摘要**：契约没有聚合/统计接口。摘要只使用 S4-02 每组响应的
  `meta.total` 做分类计数（人员组本身仅包含 `high_risk_alert`）。
  不推导 severity、状态或风险分值维度的统计。

以上三点中，“最近告警的全局合并排序”和“severity 维度高风险统计”属于契约无法支持的需求，
已按任务书要求记录为缺口，未修改契约、未虚构字段。

## 界面与交互增强（全部在契约字段内实现）

| 能力 | 实现方式 | 契约边界 |
|---|---|---|
| 深色玻璃拟态主题 | `app.wxss` 统一视觉变量与组件样式 | 纯展示层，不影响数据 |
| 相对时间 | `utils/time.js` 的 `formatRelativeTime` | 展示层派生值；naive 时间按**运行设备本地时区**解释（契约无时区，不额外附加），zoned 时间按 ISO 偏移解析 |
| 日期/类别分组标题 | `decorateListGroups` 只比较相邻项 | 不重排、不合并，保持服务端分组与排序 |
| 列表本地筛选 | `utils/filter.js`，仅过滤**已加载**视图 | 契约没有 search 参数，页面明确提示“非服务端搜索”，不发额外请求 |
| 骨架屏 / 加载动画 | `app.wxss` 的 `.sk`、`.spinner` | 纯样式 |
| 详情字段分组 + 复制 alert_key | `buildDetailView().fieldGroups`、`copyAlertKey` | 字段总数与契约一致（人员 11 / 传感器 14），复制的是 `alert_key` 原文 |
| 严重程度 / 状态快捷筛选 | 列表页本地 chips，可与关键词叠加 | 契约无查询参数；状态字段仅传感器告警存在，人员告警不参与状态筛选 |
| 触发快照对比条 | 详情页温度对 `threshold` 的可视化，阈值线取自契约字段 | 湿度没有契约阈值字段，只显示数值，不虚构阈值 |
| 分享给微信好友 | 三个页面的 `onShareAppMessage` | 分享路径只带 `alert_key`，不携带任何 Token |
| 回到顶部 + 已加载统计 | `onPageScroll` 控制悬浮按钮；统计条只统计**已加载**数据 | 统计口径明确标注“已加载 / 服务端总数”，不把客户端分页数据当成全量 |
| 表面精简 | 列表/首页只展示标题、类别、时间、严重程度 | 温度、湿度、人员 ID、风险分等细节只进详情页 |
| 详情上一条 / 下一条 | 列表跳转前把**当前已展示顺序**写入 `utils/nav-context.js`，详情页在集合内前后移动 | 只在已加载集合内导航，不做额外请求、不假设未加载数据；越界按钮禁用 |
| 本地关注 | `utils/local-store.js`，存储键 `s4_followed_keys`；详情页可关注，列表可「仅看本地关注」 | 纯本机偏好，不代表服务端状态，不同步、不上传 |
| 搜索历史 | 存储键 `s4_search_history`，最近 6 个关键词 | 纯本机记录 |
| 离线提示 | `utils/net.js` 订阅网络状态，页面顶部显示横幅 | 只提示，不伪造缓存、不回退 Mock、不改变请求行为 |
| 首页更新时间 + 手动刷新 | 加载完成后显示本机时钟 `HH:mm:ss` | 仅表示客户端最近一次加载时间 |

相对时间超过 7 天时不显示（避免长跨度口语化误导），绝对时间始终完整展示。
列表与首页不展示契约字段细节，点击条目进入详情页查看完整 11/14 个字段。

## Mock 与真实模式

- 由 `config/env.js` 的 `USE_MOCK` 控制，当前为 `true`。
- Mock 模式只调用 `mock/mock-adapter.js`，**绝不调用 `wx.request`**；
  页面顶部固定显示“当前为 Mock 演示数据，非真实后端数据”。
- 真实模式只调用 `utils/request.js`，请求失败不会回退 Mock。
- 两种模式共用同一套本地参数校验、四字段信封校验和 DTO 校验。
- Token 从本地存储键 `s4_api_token` 读取，仓库内不含任何真实 Token。

真实模式启用前仍需确定（任务书 11.2）：Base URL/端口、request 合法域名、
HTTPS 部署、Token 注入方式与生命周期、访问控制、最终错误文案。
`project.config.json` 中的 `appid` 已填为正式小程序 AppID（`wxff90e9b39021f3db`），
该值只用于开发者工具，不属于敏感信息。

## 现场影像区域与重点告警

- 首页从两组已加载的最近告警中按 severity 选取两条重点；同等级按服务端原顺序选取。重点区与展开区各自保持原分组顺序，不比较跨组时间，不代表全量风险排行。其余最近告警点击展开，全量列表仍从“全部告警”进入。
- “人员最新 / 传感器最新”分别标记对应类别返回的首条，筛选不会把其他条目重新标为最新。
- 首页、详情页提供现场图片和人员状况视频两个画幅。契约 0.1.0 的 `media_supported=false`，当前没有可展示的服务端证据地址，因此明确显示待接入。
- 本机预览仅从相册选择临时文件；不持久化、不上传、不关联告警。详情切换告警时清除预览。不能作为真实后端媒体联调证据。
- 待 B 线提供并经 A/B 确认媒体字段、事件关联及受保护访问方式后，才能接入真实影像；本次没有修改共享契约。
