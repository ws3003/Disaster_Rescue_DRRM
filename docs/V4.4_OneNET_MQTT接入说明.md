# V4.4 OneNET MQTT 传感器遥测接入说明

## 1. 作用与边界

本接入用于把树莓派 E7 采集到的传感器读数，通过中国移动 OneNET MQTT/OneJSON 作为一条独立遥测链路上报。

- SQLite、C4 同步和微信小程序后端仍是项目业务数据的权威链路。
- 阿里云 OSS 继续负责 E8 录像等媒体文件，不改为 OneNET。
- OneNET MQTT 失败不会回滚本地读数，也不会阻断 E7、E8、C4 或 OSS。
- 当前实现只做设备属性上报，不从 OneNET 反向控制设备。

## 2. OneNET 平台准备

在 OneNET 创建支持 MQTT/OneJSON 的产品和设备，并在产品物模型中建立以下属性：

| 标识符 | 建议类型 | 是否必需 | 来源 |
| --- | --- | --- | --- |
| `temp_value` | float | 是 | 当前 OneNET 产品中的 DS18B20 温度 |
| `humidity_value` | float | 否 | 预留给 DHT11 湿度；当前 DS18B20 不会上报该项 |

平台侧设备名称、产品 ID 和访问 Token 不得写入 Git。长期运行时，将设备密钥保存在树莓派的权限为 `600` 的项目外文件，并设置 `ONENET_DEVICE_KEY_FILE`；发布器会在每次 MQTT 连接或重连时即时生成新 Token，不会将 Token 写入磁盘或日志。

## 3. 项目配置

编辑 `config/onenet.yaml` 时只修改非敏感设置：

```yaml
onenet:
  enabled: true
  host: "mqttstls.heclouds.com"
  port: 8883
  tls: true
  ca_cert_path: "/home/pi/testtest/onenet/onenet-ca.pem"
  temperature_identifier: "temp_value"
  humidity_identifier: "humidity_value"
```

短期调试时可在 Edge 进程运行环境中注入：

```text
ONENET_PRODUCT_ID
ONENET_DEVICE_NAME
ONENET_ACCESS_TOKEN
```

长期运行建议改为注入如下变量（不再使用固定 `ONENET_ACCESS_TOKEN`）：

```text
ONENET_PRODUCT_ID
ONENET_DEVICE_NAME
ONENET_DEVICE_KEY_FILE=/home/pi/.config/disaster-rescue/onenet-device-key
```

密钥文件只保存设备密钥原文，权限必须为 `600`；不要把它放入仓库或 `~/testtest`。

不要把真实值写入 `.env.example`、YAML、源码、命令历史、测试报告或截图。

## 3.1 长期受控启动（systemd）

完整 EdgeClient 不只负责 OneNET：它还会按 `config/edge.yaml` 启动摄像头、E7/E8、
感知、Gateway 上传和其他已启用能力。因此只有在这些既有配置均已审核后，才安装
`deploy/systemd/disaster-edge.service.example`。该文件只是模板，不会自行启动任何服务。

树莓派的运行时文件放在项目外，示例为：

```text
/home/pi/.config/disaster-rescue/edge.env
/home/pi/.config/disaster-rescue/onenet.yaml
/home/pi/.config/disaster-rescue/onenet-device-key
```

其中 `edge.env` 可基于 `deploy/systemd/edge.env.example` 创建，包含产品 ID、设备名、
OneNET 配置路径和设备密钥**路径**；三个文件权限均应设为 `600`，目录权限设为 `700`。
设备密钥仍只存放在 `onenet-device-key`，不会写入环境文件。

`onenet.yaml` 使用上文的非敏感 OneNET 配置并设置 `enabled: true`。它可以引用官方 CA
证书的绝对路径；证书不是凭据，但也建议放在项目外并只读保存。

安装前将 systemd 样例中的项目路径核对为实际目录，再由有权限的用户执行：

```bash
sudo cp deploy/systemd/disaster-edge.service.example /etc/systemd/system/disaster-edge.service
sudo systemctl daemon-reload
sudo systemctl enable disaster-edge.service
```

只有明确批准启动完整 Edge 后，才执行：

```bash
sudo systemctl start disaster-edge.service
sudo journalctl -u disaster-edge.service -f
```

停止和回退不会删除数据或凭据：

```bash
sudo systemctl stop disaster-edge.service
sudo systemctl disable disaster-edge.service
```

## 4. 上报格式

主题：

```text
$sys/{product_id}/{device_name}/thing/property/post
```

载荷使用 OneJSON 属性上报格式。每条有效 E7 读数先写入本地 SQLite/C4，再进入有界异步 MQTT 队列。队列满或网络失败时会记录状态并重试，不阻塞传感器采样。

## 5. 本地验证

不连接真实 OneNET 的自动化测试：

```powershell
.\venv\Scripts\python.exe -m pytest -p no:cacheprovider -q `
  tests/test_onenet_config.py `
  tests/test_onenet_mqtt.py `
  tests/test_onenet_sensor_integration.py
```

真实平台验收需要在树莓派运行环境中安全注入三项凭据，然后确认：

1. OneNET 设备显示在线。
2. `temperature` 属性持续更新。
3. 使用 DHT11 时 `humidity` 属性同步更新；使用 DS18B20 时不应虚构湿度。
4. 断开 OneNET 后，本地 E7、E8、C4 和阿里云 OSS 仍正常工作。
5. 恢复网络后 MQTT 自动重连并继续上报。

## 6. 当前未包含的能力

- 微信小程序直接访问 OneNET。
- 后端从 OneNET 拉取历史遥测。
- OneNET 命令下发或远程控制。
- MQTT 消息的本地持久化补发队列。

如后续需要让小程序读取 OneNET 数据，应由后端使用受控凭据访问 OneNET，再向小程序提供 HTTPS 用户接口；不得把 OneNET Token 放入小程序。
