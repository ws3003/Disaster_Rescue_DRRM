# V4.4 OneNET MQTT 传感器遥测接入说明

## 1. 作用与边界

本接入用于把树莓派 E7 采集到的传感器读数，通过中国移动 OneNET MQTT/OneJSON 作为一条独立遥测链路上报。

- SQLite、C4 同步和微信小程序后端仍是项目业务数据的权威链路。
- 阿里云 OSS 继续负责 E8 录像等媒体文件，不改为 OneNET。
- OneNET MQTT 失败不会回滚本地读数，也不会阻断 E7、E8、C4 或 OSS。
- 当前实现只做设备属性上报，不从 OneNET 反向控制设备。

## 2. OneNET 平台准备

在 OneNET 创建支持 MQTT/OneJSON 的产品和设备，并在产品物模型中建立以下属性：

| 标识符 | 建议类型 | 是否必需 | 来源 |
| --- | --- | --- | --- |
| `temperature` | float | 是 | DS18B20 或 DHT11 温度 |
| `humidity` | float | 否 | DHT11 湿度；DS18B20 不会上报该项 |

平台侧设备名称、产品 ID 和访问 Token 不得写入 Git。真实 Token 应按 OneNET 的有效期和权限策略生成，并定期轮换。

## 3. 项目配置

编辑 `config/onenet.yaml` 时只修改非敏感设置：

```yaml
onenet:
  enabled: true
  host: "mqttstls.heclouds.com"
  port: 8883
  tls: true
  temperature_identifier: "temperature"
  humidity_identifier: "humidity"
```

在 Edge 进程运行环境中注入：

```text
ONENET_PRODUCT_ID
ONENET_DEVICE_NAME
ONENET_ACCESS_TOKEN
```

不要把真实值写入 `.env.example`、YAML、源码、命令历史、测试报告或截图。

## 4. 上报格式

主题：

```text
$sys/{product_id}/{device_name}/thing/property/post
```

载荷使用 OneJSON 属性上报格式。每条有效 E7 读数先写入本地 SQLite/C4，再进入有界异步 MQTT 队列。队列满或网络失败时会记录状态并重试，不阻塞传感器采样。

## 5. 本地验证

不连接真实 OneNET 的自动化测试：

```powershell
.\venv\Scripts\python.exe -m pytest -p no:cacheprovider -q `
  tests/test_onenet_config.py `
  tests/test_onenet_mqtt.py `
  tests/test_onenet_sensor_integration.py
```

真实平台验收需要在树莓派运行环境中安全注入三项凭据，然后确认：

1. OneNET 设备显示在线。
2. `temperature` 属性持续更新。
3. 使用 DHT11 时 `humidity` 属性同步更新；使用 DS18B20 时不应虚构湿度。
4. 断开 OneNET 后，本地 E7、E8、C4 和阿里云 OSS 仍正常工作。
5. 恢复网络后 MQTT 自动重连并继续上报。

## 6. 当前未包含的能力

- 微信小程序直接访问 OneNET。
- 后端从 OneNET 拉取历史遥测。
- OneNET 命令下发或远程控制。
- MQTT 消息的本地持久化补发队列。

如后续需要让小程序读取 OneNET 数据，应由后端使用受控凭据访问 OneNET，再向小程序提供 HTTPS 用户接口；不得把 OneNET Token 放入小程序。
