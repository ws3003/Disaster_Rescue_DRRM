# V4.1 Assistant 真实链路验证报告

> 分支：`feature/v4.1-assistant`
> 本文档为只读验证记录，未修改任何 `src/`、`server/`、`config/` 文件。

## 1. 验证目标

验证 V4.1 核心闭环「灾害现场人员状态 → Assistant 信息问答」，具体确认：

- Pi 端视觉结果（person_events）能否上传到 Windows Server
- Server 能否接收并保存 Vision Snapshot
- Assistant 能否读取并回答「现场有几个人」「现场图片在哪里」
- 回答中能否返回现场图片 URL

## 2. 系统链路

```
Pi Edge (摄像头 → YOLO26n + MediaPipe → person_events)
   │
   ▼  VisionClient.upload(person_events)  [POST /api/v1/vision/snapshot]
FastAPI (Windows Server, uvicorn server.api:app)
   │  写 data/vision_persons.json
   ▼
AssistantContext 读取 vision_persons.json
   │
   ▼  POST /api/v1/assistant/ask
Assistant 自然语言回答(人员数量 / 状态 / 风险 / 现场图片 URL)
```

## 3. 验证环境

| 项 | 说明 |
|---|---|
| Windows Server | FastAPI；命令 `uvicorn server.api:app --host 0.0.0.0 --port 8000`；Python venv |
| Raspberry Pi | `python src/edge_client.py --once`；Camera + YOLO26n + MediaPipe |
| 网络 | Pi → Server（局域网，`192.168.43.206`） |

## 4. 验证过程

按时间顺序：

- **Step 1**：Pi 运行 `python src/edge_client.py --once`，完成摄像头采集、YOLO26n 检测、MediaPipe 姿态、人员状态识别。
- **Step 2**：产生 person_events（含 person_id / state / risk_score / priority）。
- **Step 3**：Server 经 `/api/v1/vision/snapshot` 接收并写入 `data/vision_persons.json`（含每人的 `image_url`，来自 server 最近一次分析快照）。
- **Step 4**：调用 `POST /api/v1/assistant/ask`，Assistant 读取 vision snapshot 返回人员数量、状态、风险与现场图片 URL。

## 7. 已知限制

- 当前 `image_url` 来自 **server 的快照机制**（`data/snapshots` 中最近一次分析图），**不是**新增的独立图片上传链路。
- `image_url` 指向的是 server 端"最近存在"的快照文件；由于 Pi 在 `perception.analyze()` 之后、`EdgeUploader.upload()`之前推送 vision，极短时序下可能滞后到上一帧快照。对"最近现场图片"语义影响较小。
- 该增强**不影响原 V4.0 报警链**（analyze / OSS / communication_tool / DingTalk 未改动）。
