| 401 | `UNAUTHORIZED` | 缺失、无效或过期的认证凭证 |
| 403 | `FORBIDDEN` | 身份有效但权限不足 |
| 404 | `NOT_FOUND` | 格式合法但对应资源不存在 |
| 422 | `VALIDATION_ERROR` | 语义校验失败，例如 `start > end` |
| 500 | `INTERNAL_ERROR` | 未预期的服务端错误 |

注意事项：

- 401/403 错误响应采用四字段信封：`code`（已批准错误码）、`message`（错误描述）、`data=null`、`meta={}`。
- ID 格式非法归入参数错误（400），与资源不存在（404）区分。
- 格式合法但查无记录，归入 404。
- `E-` 前缀合法但后续日期段、长度或字符不符合格式，仍属格式错误（400），**不得归入 404**。
- `[代码核验结果]` 在未确认实际格式规则前，不得假设 ID 是整数或完整 UUID（§12.5 已核实为 `E-<YYYYMMDD>-<UUID8>` 文本格式）。

### §12.4 分页与排序

`[用户已确认设计决策]`，保留此前批准方案，原样：

- 分页元数据统一放在 `meta` 中；列表接口的 `meta` 包含 `page`、`page_size`、`total`、`has_more`。
- `page` 默认值 1。
- `page_size` 默认值 20。
- `page_size` 最大值 100。
- 首版实现需 COUNT 与合并分页。
- 筛选条件必须影响 `meta.total`。
- `meta.has_more = meta.page * meta.page_size < meta.total`。
- 空列表返回 `data=[]`、`meta.total=0`、`meta.has_more=false`。
- `total` 与 `has_more` 属于 `meta` 字段，**不得定义为 `data` 的同级字段**。
- 非分页接口不得强行套用分页字段；`meta` 按已批准统一结构使用空对象 `{}` 或适用的非分页元数据，**不得虚构额外字段**。

人员告警排序：

1. `events.ts DESC`
2. `event_id DESC`

传感器告警排序：

1. `sensor_alerts.occurred_at DESC`
2. `alert_id DESC`

### §12.5 告警标识、来源与 DTO
