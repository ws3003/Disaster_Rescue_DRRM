# V4.0 Edge Demo Deployment

> Disaster_Rescue_DRRM · 城市灾害边缘哨兵 · **V4.0 Edge Demo 部署指南**
> 供比赛展示人员使用。当前版本 Tag: `v4.0-edge-demo`

本系统实现: 树莓派边缘实时感知 (YOLO26n + MediaPipe) + 人体状态识别 + 风险排序 + 图片上传到 Windows FastAPI Gateway → Cloudflare Tunnel 公网访问 → DingTalk 钉钉机器人报警 (文字 + 现场图片)。

---

## 1. 系统架构

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│   Raspberry Pi 5 (Edge)    │        │   Windows Server (Cloud)      │
│  ┌──────────────────────┐  │        │  ┌────────────────────────┐  │
│  │ Camera (Picamera2)   │  │        │  │ FastAPI Gateway        │  │
│  │   → YOLO26n 检测      │  │        │  │  POST /api/v1/analyze  │  │
│  │   → MediaPipe 姿态    │  │        │  │  GET  /snapshots/{fn}  │  │
│  │   → 状态/风险/排序     │  │        │  │  (VLM+LLM+Snapshot)    │  │
│  │   → edge_client       │  │        │  └──────────┬─────────────┘  │
│  └──────────┬───────────┘  │        │             ▼                 │
│             │ 上传图片      │        │  ┌────────────────────────┐  │
│             └──────────────┼───────▶│  │ Cloudflare Tunnel      │  │
└────────────────────────────┘        │  │  公网 base_url         │  │
                                      │  └──────────┬─────────────┘  │
                                      │             ▼                 │
                                      │  ┌────────────────────────┐  │
                                      │  │ DingTalk 机器人报警      │  │
                                      │  │  (文字 + 现场图片)      │  │
                                      │  └────────────────────────┘  │
                                      └──────────────────────────────┘
```

数据流: **摄像头 → 检测 → 姿态 → 状态 → 风险 → 排序 → 上传 → VLM/LLM → SnapShot → 钉钉报警**

## 2. Windows 端启动

### 2.1 启动 API Gateway

在 Windows 项目目录:

```bash
# 进入虚拟环境 (若有 venv)
# 安装依赖 (server/VLM/LLM)
pip install -r requirements.txt

# 配置环境变量: Qwen VLM/LLM 的 API Key (若用真实 qwen)
#   VLM_API_KEY=...
#   LLM_API_KEY=...
# 缺省可用 mock provider 跑通链路

# 启动统一 Gateway (单端口同时提供 analyze + snapshots)
uvicorn server.api:app --host 0.0.0.0 --port 8000
```

验证:
- 浏览器访问 `http://localhost:8000/docs` → 有 `/api/v1/analyze` 与 `/snapshots/{filename}` 两个端点。
- `http://localhost:8000/snapshots/<某analysis.jpg>` 能显示图片。

### 2.2 启动 Cloudflare Tunnel

用 `cloudflared` 建立公网隧道, 把本机 8000 端口暴露为公网 URL:

```bash
cloudflared tunnel --url http://localhost:8000
```

会输出一个形如 `https://xxxx.trycloudflare.com` 的公网地址。(注意: 每次启动隧道地址都会变。)

### 2.3 修改 storage.yaml 的 base_url

把 `config/storage.yaml` 中 `storage.local.base_url` 改成本次隧道的公网地址:

```yaml
storage:
  provider: local
  local:
    base_url: "https://本此隧道地址.trycloudflare.com"
```

> 关键: **必须用公网地址**, 不能写局域网 IP (如 `http://192.168.43.206:8000`), 否则钉钉服务器拉到图片地址时会因无法访问局域网而显示失败。

## 3. Raspberry Pi 启动

在树莓派上:

```bash
# 1) 进入项目目录
cd Disaster_Rescue_DRRM

# 2) 一键启动
./run_demo.sh
```

等价于手动执行 `python src/edge_client.py --preview`。

`--preview` 会:
- 打开实时摄像头预览窗口 (叠加 person_events 文字)
- 周期性 `POST` 上传图片到 `config/edge.yaml` 的 `server.api_url`
- 对 HIGH 人员保留现场快照, 并优先使用 server 返回的 `snapshot_url`、否则本地快照
- 经 Agent → 通信链到钉钉回发

> headless / 无桌面环境: 无窗口可关, 直接 `Ctrl+C` 退出。

## 4. Demo 测试流程

展示时的标准操作路径:

1. **摄像头采集**: 树莓派摄像头拍摄现场 (人或演示对象)。
2. **YOLO 检测**: 识别出人员 (civilian / rescuer)。
3. **MediaPipe 分析**: 33 关键点人体姿态。
4. **状态判断**: Standing / Sitting / Lying / Fall / Help-Waving。
5. **风险输出**: 每人产 `risk_score` + `priority`(HIGH/MEDIUM/LOW), 并排序。
6. **图片上传**: `edge_client` 把当前帧上传到 Windows Gateway。
7. **Server 处理**: VLM/LLM 分析场景 → 保存 snapshot → 返回 `snapshot_url`。
8. **钉钉报警**: 触发 HIGH 风险时, 钉钉机器人推送文字报警 + 现场图片 (经公网隧道可访问)。

观察点 (日志/输出):
- 树莓派侧: `[Perception] person_events`、`[Snapshot] using remote snapshot_url / saved`
- 钉钉侧: 收到 `🚨 灾害报警` 文字 + 可点开的现场图片

## 5. 常见问题

### Q1: Cloudflare 隧道地址变化
- 现象: 之前能看图, 重新启动隧道后图片打不开。
- 原因: `cloudflared` 每次启动生成新的随机隧道子域名。
- 解决: 重启隧道后, **同步更新 `config/storage.yaml` 的 `local.base_url`**, 并重启 Windows API Gateway (或确保 server 读到新配置)。若 edge 端已缓存旧的 `snapshot_url`, 重新上传一张触发新 URL 即可。

### Q2: 摄像头无法打开
- 现象: `python src/edge_client.py --preview` 报摄像头错误。
- 检查, 依次排查:
  1. 是否装了系统包: `sudo apt install python3-picamera2`
  2. 是否以正确用户/权限运行 (CSI 摄像头可能需要非 root 但需组成员)。
  3. 是否被其他进程占用摄像头。
  4. `config/edge.yaml` 的 camera 分辨率/帧率是否被摄像头支持 (默认 1280x720)。

### Q3: API 无法连接
- 现象: edge 端打印 `[EdgeClient] API connection failed`。
- 排查:
  1. Windows Gateway 是否启动 (浏览器访问 `http://<IP>:8000/docs`)。
  2. `config/edge.yaml` 的 `server.api_url` 是否指向 Gateway 的局域网 IP + 端口 (例如 `http://192.168.43.206:8000/api/v1/analyze`)。
  3. 树莓派与 Windows 是否同一局域网、能否 ping 通。
  4. 防火墙是否放行 8000 端口。
  5. 若需跨公网, 则走 Cloudflare (edge 指向隧道地址而非局域网 IP)。

### Q4: 钉钉收到报警但图片显示占位符
- 现象: 文字报警正常, 图片不显示。
- 原因: 图片 `picURL` 指向的地址钉钉拉不到 (通常是局域网 IP, 钉钉服务器无法访问)。
- 解决: 按 §2.3, 确保 `snapshot_url` 用 `config/storage.yaml` 的公网隧道 base_url, 而非请求的局域网 host。修改后重启 Gateway 并重新触发一次报警。
