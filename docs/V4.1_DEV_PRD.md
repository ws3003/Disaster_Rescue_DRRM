## 第二部分：V4.1 Assistant 目标

定位：**灾害现场信息辅助决策助手**。

即：向现场人员 / 指挥者提供**信息类、决策支撑类**的问答与数据呈现，帮助人更快的了解现场并**由人做出决策**。

V4.1 **不**替代、**不**绕过、**不**发起下列动作（本项目口径中明令禁止描述/实现）：
- **自动救援**
- **自动调度**
- **替代人工决策**

所有工具仅呈现信息；任何救援动作仍由既有 V4.0 决策链与人工确认完成。

```
             User
              |
              v
      Assistant Layer   (src/assistant 会话编排)
              |
```

与 V4.0 的关系：

| 层 | 职责 |
|---|---|
| V4.0 | 感知与任务执行（检测/识别/风险/推理/任务/报警） |

V4.1 叠加在 V4.0 之上，复用其既有事实（Agent 最近状态、SQLite、OSS snapshot_url、实时分析结果），作为 AssAsstant 上下文。

## 第四部分：新增模块规划

### 4.1 Assistant 会话编排层 `src/assistant/`
- `context.py` — 聚合现场上下文：Agent 最近状态 + SQLite + OSS snapshot_url + 天气 + 位置/路线。
- `intent.py` — 文本/语音意图规整（辅助解析"现场/天气/路线"类提问）。
- `responder.py` — 基于聚合上下文 + LLM 生成**决策辅助口径**的自然语言答复。

### 4.2 服务端 API `server/`
- `/api/v1/assistant/ask` — 提问 → 聚合上下文 → LLM 答复。
- `/api/v1/assistant/tts` — 答复文本 → 语音回播（音频）。
- （可选只读）`/weather`、`/map/route` 供前端/边缘侧查询天气与路线建议。

### 4.3 信息类工具 `src/tools/`
- `weather_tool` — `get_current(lat,lng)` 返回现场天气（条件/温度/风力/降水/有无预警）。仅信息。
- `map_tool` — `geocode(地址)` 定位 / `rescue_route(起,终)` 路线建议。仅建议文本，不派单。
- **voice 作为独立交互层，不直接进入 Executor 执行链**：语音(ASR/TTS)由 `voice_tool` 在 Assistant 交互层使用，**不能**被 Agent 决策链自动触发成动作。

工具守 V4.0 契约（`Tool` + `input_schema` + `run(**kwargs)`），但语义上**全部只读、信息类**，实施方案前需串行在 Executor 无害注册或仅由 Assistant 层调用（按阶段决定）。

## 第五部分：开发阶段规划

| 阶段 | 内容 | 验收要点 |
|---|---|---|
| **Phase 1**：Assistant 文本问答框架 | `src/assistant/context.py + intent.py + responder.py` + `/assistant/ask` | 离线 mock 下，文本提问返回自然语言答复；不做任何动作 |
| **Phase 2**：天气信息接入 | `weather_tool` + 把天气并入分析/回答上下文 | `ask("现场天气")` 返回天气；分析链含 weather_note |
| **Phase 3**：地图/GIS 信息接入 | `map_tool`(geocode / rescue_route) | 支持灾地点定位与路线建议；仅文本建议 |
| **Phase 4**：语音交互 | `voice_tool`(ASR/TTS) + `/assistant/tts` | 语音提问→文本→答复→语音回播闭环 |

每个阶段：先 mock provider 过离线测试，再上真实凭据；逐阶段做小步回归。
