# V4.4 单租户共享数据与媒体访问规则

- **适用范围**：Disaster_Rescue_DRRM V4.4 B 线（`feature/v4.4-b-backend`）
- **架构决策（已由负责人正式确定）**：采用**单租户共享数据模式**。
- 本文件固化该决策及媒体访问的安全约束，作为实现与验收的规则基准。

## 1. 设计背景

V4.4 是在 V4.3 完整功能上的增量扩展。一套 Edge 系统上报的告警与媒体证据面向该系统所有有效登录用户共享，不做个人所有者的隔离。原因：业务数据产生于单一边缘设备/单个部署，不区分数据归属到具体微信用户；为每个告警绑定个人归属在业务上没有依据。

## 2. 核心原则

- 所有**成功登录的微信用户**共享同一套系统业务数据。
- 不存在告警记忆人所有权隔离。
- 不存在媒体记忆人所有权隔离。
- 微信 Session 仍负责用户身份**认证**；未登录、过期或撤销的用户不能访问受保护接口。
- 不新增 `user_id`/`device_id` 告警归属字段，不新增 `alert_access` 表，不进行历史数据归属迁移。

## 3. 用户身份与认证

- `users` 表维护用户身份：`user_id`(PK)、`wechat_openid`(UNIQUE)、`created_at`。
- `sessions` 表负责会话：`session_id`(PK)、`user_id`(FK)、`session_token_hash`(仅 SHA-256，UNIQUE)、`created_at`/`expires_at`/`revoked_at`。
- 登录：微信 `code2session` → 内部用户（一 openid 一用户）→ 建 Session(24h) → 返回**一次明文** `session_token` + `expires_in` + `user_id`。
- 认证：`server/auth.py::get_current_user` 解析 Bearer Session Token → 查 `session_token_hash` → 校验存在/撤销/过期 → 返回当前用户；失败返回 401。
- `users`/`sessions` 只承担身份认证职责，不参与业务数据的归属过滤。

## 4. 告警数据访问规则

- `events`（人员事件）与 `sensor_alerts`（传感告警）为**全系统共享数据**，不按用户隔离。
- 任何有效登录用户可查询同一套告警；服务端查询**不带 `user_id` 过滤**（业务表亦无该列）。

## 5. 媒体数据访问规则

- `media_evidence` 为**全系统共享媒体清单**，不按用户隔离。
- 任何有效登录用户可列出并申请访问同一套已上传成功的媒体证据。
- 媒体访问仍受认证与"已上传成功"双重状态门控约束（见 §7）。

## 6. 媒体接口

### 接口 A：`GET /alerts/{alert_key}/media`（告警关联媒体元数据列表）

- 认证：微信 Session Bearer（`get_current_user`）。
- 请求参数：`alert_key`（`person:<event_id>` 或 `sensor:<alert_id>`）、可选 `page`/`page_size`。
- 返回：四字段信封 `{code,message,data,meta}`；`data` 为媒体元数据数组，每项为 `media_id/media_type/status/upload_status/captured_at/uploaded_at`；`meta` 含 `page/page_size/total/has_more`。
- 人员告警当前无媒体（`media_evidence.source` 仅 sensor），返回空数组。
- **绝不返回** `object_key`、`local_path`、Bucket、永久访问 URL。

### 接口 B：`POST /media/{media_id}/access`（签发短期 GET 签名 URL）

- 认证：微信 Session Bearer。
- 请求参数：`media_id`。
- `object_key` **由服务端从数据库读取**；客户端不得指定/覆盖 `object_key`/`bucket`/`endpoint`/`access_url`。
- 媒体必须同时满足 `status == 'success'` 且 `upload_status == 'success'` 才签发；否则 409。
- 签名有效期 **300 秒**，经 `src/storage.py::sign_get_url(object_key, ttl=300)` 生成。
- 返回：`data` 含 `access_url`（短时签名 URL）与 `expires_at`（UTC ISO 8601）；过期后可重新调用本接口刷新。

## 7. 媒体访问安全要求

- 两个媒体接口均要求有效微信 Session。
- `object_key` 仅服务端数据库读取，客户端不可指定。
- 双重成功门控：`status == success` 且 `upload_status == success`。
- 300 秒短时签名 URL，防长时公开直链。
- 不向客户端泄露 `object_key`/`local_path`/Bucket。
- 未登录/无效会话 → 401；媒体不存在 → 404；未上传成功 → 409；签名服务不可用 → 503；其他 → 500。

## 8. 与 S4 服务 Token 的区别

- **微信 Session Bearer**（`get_current_user`）：表示**登录用户身份**，用于媒体等需要用户身份的业务。
- **S4 服务 Bearer**（`server/s4.py::_require_s4_token`，来自 `S4_API_TOKEN`）：表示**服务调用凭证**，用于服务端只读查询。
- 两者不可混用；不得把 S4 服务 Token 暴露到小程序前端。

## 9. V4.3 兼容性

V4.4 媒体授权为**新增增量**，不得替代或删除 V4.3 既有链路；以下保留并须回归：

- 原有 `/api/v1/analyze` 与 `snapshot_url`。
- 本地 `data/snapshots` 与 `/snapshots/*` 静态访问。
- Assistant 图片/问答、VLM 图像读取、DingTalk 图片通知。
- 本地图片/视频证据保存与既有访问能力。
