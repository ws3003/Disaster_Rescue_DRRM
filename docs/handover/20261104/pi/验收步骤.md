# B 线树莓派验收步骤

## 首次连接：只读盘点

收到 IP、SSH 用户、端口及认证方式后，先记录系统/架构、Python、磁盘、时区，实际代码目录的 Git 分支、提交和工作区状态，以及已有采样/摄像头/同步进程。核对 One-Wire 设备 ID 与配置。凭据仅检查是否配置，不打印内容。

已有进程使用摄像头时，不能直接启动另一个独占采集进程；任何停止服务、切分支、依赖升级和现场阈值修改，都需先核对影响与授权。

## 真实闭环

1. 备份设备代码配置和数据库；测试使用独立数据库，保护未提交修改。
2. 连续读取 DS18B20 真实温度，验证无效读数、断线和恢复。湿度来源独立确认，不使用 Fake 湿度代替真实采集。
3. 在隔离测试配置下验证一级报警、二级升级、冷却、恢复、进程重启。
4. 由真实二级告警触发实际约 10 秒录像，确认同一 CameraService 与识别共享正常、颜色正确、文件可播放，停止后资源释放。
5. 补齐并验证生产入口上传器接线，再检查真实 OSS 成功、失败暂存、重试、重启恢复和受保护访问。
6. Pi→PC 的 C4 验证正常、重复、断网、恢复及重启；同一事件不能重复入库。
7. 云端真实推理验证成功、超时、暂停和恢复；失败时本地识别/告警继续运行，并执行 SRS 本地回归。
8. 明确微信用户会话与 S4 查询鉴权、媒体接口规格后，手机查询同一真实告警并查看明确关联的图片/视频。

## 每项证据

记录日期、设备、提交、命令、测试配置、预期、实际结果、通过/失败/未执行；保存 alert_key、reading_id、media_id 和日志/文件位置。不要在报告中附带真实 Token、AppSecret、OSS 密钥或完整敏感数据库。

Mock 测试通过、在 Pi 上运行模拟测试、真实硬件全链路通过，分别记录。
