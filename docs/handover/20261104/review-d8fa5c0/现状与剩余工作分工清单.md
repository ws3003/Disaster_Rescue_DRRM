## 8. GitHub 交付纪律与提交顺序

### 文件所有权与单包交付

1. 一个包对应一个清晰提交或一个小型相关提交序列；只提交该包代码、相关测试及该包独立报告。跨层必需变更同包注明，不拆到无法运行。

4. 契约只有一个权威来源和负责人。A 经确认后同步正式快照，不把 B 整条分支直接合入 A 来“拿一个 JSON”。后续版本提交必须写清契约来源。
5. 各包报告用 `docs/acceptance/<包编号>-<说明>.md`，不让所有人同时改一个总报告；集成人统一更新总索引。
6. 每次交付说明：起始/结束提交、契约版本、文件清单、测试命令及通过/失败/跳过/告警、未验证环境、配置变量名与回退方法。
7. 不提交 .env/Token/AppSecret/OSS 密钥、运行库、权重、未脱敏现场影像、缓存、临时输出。Pi 上的修改经比对回到代码提交，不能留成仅设备上的“隐藏补丁”。
